# 2026-09-26 — Rename a frame from its header

Branch `claude/focused-euler-tysk97`, on top of c798e1b. No format change, so no
schema, CHANGELOG or version bump.

## The ask

A screenshot of a frame with its "Frame" header, and "Allow renaming the frame
header." Until now the name could only be changed in the style panel. The frame
module and `docs/05-interactions.md` both said the name was "deliberately not
clickable".

## What changed

- **Double-click (or double-tap) the name** opens an in-place editor on it,
  with the name selected (caret at the end on a coarse pointer, as in the text
  editor). **Double-clicking the border** does the same, which is the only way
  to name a frame whose name is empty, since it draws no tab.
- Enter or Escape finishes (Escape keeps what was typed, matching the text
  editor), and so does a press anywhere else. The dismissing press does nothing
  else. One "Rename frame" undo step. An unchanged name writes nothing and
  does not mark the board dirty.
- The style panel's name row is unchanged.

### Where it lives

- `render/shapes/frame.ts`: `frameNameBox(frame)`, the one description of the
  name tab's box (local frame, baseline `FRAME_NAME_GAP` above the top edge,
  top `BASELINE_RATIO` em above that, as wide as the name measures). New
  constants `FRAME_NAME_WEIGHT`, `FRAME_NAME_COLOR` and `FRAME_NAME_FONT`, now
  shared by `draw` and the SVG exporter instead of literals.
- `input/hitTest.ts`: `frameNameAt` picks a name tab (back to front, tolerance,
  skipping locked, hidden and unnamed frames). `frameToRename` decides a
  double-click. The tab wins unless something painted later covers it, but
  never loses to one of the frame's own members, which are clipped away there.
  Otherwise it returns a border-hit frame. `hitTest` itself is untouched, so a
  single click on the name still selects nothing.
- `input/controller.ts`: `editTextAt` asks `frameToRename` first and calls the
  new `onRenameFrame` option.
- `ui/frameNameEditor.ts` (new): `FrameNameEditor`, an `<input>` (one line,
  fixed typography, sized to the text on every keystroke with 2 units of
  slack). It hides the canvas name through `displayed`, sets `editingId`, and
  writes once on commit. No transient edits.
- `ui/dom.ts`: `listenForOutsidePress`, extracted from `TextEditor`, which now
  uses it too. Same timing rules (a task later, bubble phase). `open` now also
  drops a previous listener before adding one.
- `app/app.ts`: `commitEditing()` commits both editors and replaces every
  `textEditor.commit()` call site. `displayed` composes both editors. Both
  editors reposition on viewport, load and resize.
- `styles/app.css`: `.mf-frame-name-editor`, with the text editor's accent ring
  and a dimmed placeholder ("Frame name").

## The baseline

The first version borrowed the text editor's `cssBaselineOffset` (a `<div>`
probe). The editor's text was 1px low. Chromium lays an input's line out at the
font's *normal* height and centres it in the box, whatever `line-height` says.
Measuring an inline-block input with a baseline marker still left it 0.375px low
at `line-height: 1.25`, because painting rounds the fractional centring. The fix
was `line-height: normal` and no set height. The textEditor export was then
reverted, since nothing else needs it. Verified by comparing grey-ink bounding
boxes of screenshots before and during editing. At 4× zoom they are identical,
with the same ink count (2891). At 1× they agree within a pixel horizontally
(antialiasing). Logged in LEARNINGS.md.

## Noticed, not changed

- The frame name's colour (`#6b7280`) is not in `docs/03-elements.md`, so an
  external renderer cannot reproduce it exactly. Adding it is a documentation
  clarification, which the changelog rules call a patch bump, so it was left
  for a separate change.
- A single click or drag on the name still does nothing (the documented
  decision). Tools like Figma and Excalidraw select and drag a frame by its name.
  That would need the tab in selection and move picking too, and was out of
  scope.
- The right-click menu has no Rename entry for a frame.

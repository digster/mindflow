# 2026-08-20 — A `table` element, and the undo bug it uncovered

Branch `claude/table-object-sb39de`. Schema **1.2.0 → 1.3.0**.

## The ask

> add a table object that can be used.

"That can be used" set the bar: a grid that only renders is a picture of a table.
The deliverable is a type you can create, type into cell by cell, re-proportion,
add rows and columns to, save, reload and export.

## The one modelling decision everything else follows from

**`columns` and `rows` hold proportions, not lengths.** A track renders at
`track / Σ tracks × boxDimension`.

Absolute lengths were the obvious choice and are wrong here. They create a second
description of how big the table is, which then has to be kept in step with
`width`/`height` on every resize — meaning a type-specific resize path in
`input/transform.ts`, which is forbidden from knowing what a table is, and a file
format carrying an invariant that can silently break. With proportions, resizing
a table is the ordinary base-geometry change every other type gets and no code
outside `shapes/table.ts` learns anything new.

Everything that *does* change structure (insert, delete, drag a divider) adjusts
the box as well as the tracks, in the ratio that keeps `total / Σ` constant — so
every track the user did not touch keeps its rendered size. Adding a row makes
the table taller rather than squeezing the rows already there.

MindFlow writes equal tracks as `1`s, so `[2, 1, 1]` reads as *"the first column
is twice as wide"* rather than as a pair of pixel counts that stop being true
after the first drag.

Also decided, and recorded in the changelog with reasons: cells are plain strings
in a row-major array (not objects); typography is one set of fields on the
element; merged cells are not modelled; one header axis, not two.

## Two new registry extension points

Both optional, so no existing type changed, and both exist to keep the
no-branching-on-`type` rule intact rather than to be general for its own sake.

**`textRegions` / `textRegionAt` / `withRegionText`.** A table owns many
independent blocks of text, and "which one am I editing?" had to be expressible
without the text editor, the controller or the search index knowing what a cell
is. An opaque key plus a local-frame box is all any of them need.
`capabilities.text` now means "owns its text directly, addressed by region"
rather than "has a `text` field", which is why the style panel's typography row,
double-click-to-edit and find-on-board all worked with no per-type code.

`TextRegion.fontWeight` exists for one reason: a header cell is drawn semibold,
and the DOM overlay has to match the canvas or the text visibly thins the moment
editing starts.

**`interiorHandles` / `dragInteriorHandle`.** Draggable dividers *inside* an
element. The controller offers the gesture with the same hit slop and the same
zoom division the outer resize handles use, and never learns that what it is
dragging is a column boundary. The cursor (`col-resize` / `row-resize`) is the
whole affordance — drawing chrome on every gridline would clutter the thing it
sits on. Dividers are offered only on a single selected, unlocked element.

## The bug this uncovered

Writing the "each tabbed cell is its own undo step" test failed, and the cause
was not in any of the new code: **undo after a text edit had never worked, for
any element type.** Type into a sticky, press Escape, `Cmd+Z` — the text stays.

`TextEditor.commit`'s rewind read the element back out of the document, but
`onInput` had already written every keystroke there transiently. So the rewind
restored the typed state to itself, and the command it pushed carried identical
content in `before` and `after` — a live undo entry that undid nothing.

Nothing caught it because every proxy was true: the board went dirty, the element
changed, the undo button enabled, the stack had an entry. Only asserting on the
document *after* an undo reveals it.

Fixed by capturing the element at `open` and rewinding to that, with
`replaceElements` (which reads `before` from the live document) instead of
`updateElements` (which skips a patch whose updater returns the object it was
given). Two regression tests on a sticky note, deliberately not on a table — the
bug is general and the test should say so.

## Tests

316 unit/contract (was 283) and 97 e2e (was 83). Typecheck clean, `index.html`
rebuilt and committed.

New unit file `test/unit/table.test.ts` (33 cases) pins what an external tool has
to reimplement: proportional tracks, the exact cell grid, structural edits
leaving untouched tracks alone, and the loader's leniency (padding short rows,
stringifying numeric cells, inferring a missing shape from `cells`, repairing a
non-positive track rather than dropping it — dropping one would shift every cell
after it into the wrong column).

Twelve e2e cases under `tables` drive the real UI, plus two under `undoing a text
edit` for the bug above. Rendering was also checked in a real browser: header
band, wrapped cell text, hairline grid, and a divider drag widening one column.

## Not done, deliberately

- **Merged cells and per-cell styling.** Reasons in the changelog; `meta` is the
  escape hatch.
- **A header column.** One axis covers the overwhelming majority of tables.
- **Clipping cell text in SVG export.** The canvas clips, the exporter does not —
  matching how `sticky` already behaves. Wrapping means it only arises
  vertically. Now stated in `07-rendering.md` rather than left to be discovered.
- **Pasting a TSV/CSV block into a table.** The obvious next feature, and a real
  one: it would make importing a spreadsheet a paste rather than a typing
  session.

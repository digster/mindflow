# 2026-09-28 — Saves that finish after the board changed

Branch `claude/friendly-fermi-mhzq8i`, a second commit on top of 90d9f95 (the
save spinner, not yet merged). No format change.

## The ask

"Work on the suggested task now." The task was yesterday's "Noticed, not
changed": both save paths awaited the write and then called
`store.markSaved(origin)` on whatever board was on screen when it landed.

1. Edits made during a save lost their dirty flag, although the file lacked
   them. The dirty dot, `beforeunload` and the recent *Unsaved* tag all went
   quiet.
2. A board opened during a save took the old board's origin and went clean, so
   its next Cmd+S would overwrite the old board's file or Drive copy.

## What changed

- **`store.ts`**: `SaveTicket { boardId, generation, revision }` and
  `SaveOutcome`. `generation` is bumped by `load` and `reset` (through the new
  private `replaceBoard`, which first records `departed`). `revision` is bumped
  by the new private `markEdited` (execute, including transient; undo; redo;
  addFiles) and by `markDirty` even when already dirty. `saveTicket()` and
  `completeSave(ticket, origin)`:
  - same generation and revision → `markSaved` → `clean`
  - same generation, newer revision → `setOrigin` only, stays dirty →
    `edited`. This keeps a first Drive save's new file id, so the next save
    updates rather than creating a second file.
  - different generation → nothing touched. `left-as-saved` if it was the
    most recently departed board, departed at the ticket's revision, and no
    board with its id is on screen. Otherwise `left`.
  - `markSaved` kept (the e2e suite calls it directly). Its doc says awaiting
    saves must use `completeSave`.
- **`app.ts`**: `snapshotForSave()` (ticket + `documentForSave` + preserved, in
  one synchronous step) and `recordSave(written, origin)`. On `left-as-saved`
  it rewrites the left board's autosave copy with `unsaved: false`.
  - `saveToDrive` now snapshots before awaiting `resolveFolder` (latent: the
    folder is always cached in practice).
  - `writeBoard` snapshots after the Drive branch, still before any await.
  - `requestSave` (the queued-save guard from yesterday) now compares the
    generation, not the id, so a board reopened from recent counts as a
    different board.

### Why the copy is only cleared in the narrow case

`Autosave.schedule` replaces a pending snapshot with the same board id. So
rewriting the copy of a board that is open again could drop that board's
pending edits. When it cannot be sure, it leaves the *Unsaved* tag. That can
only mislabel a saved board, never lose data.

## Noticed, not changed

- The success toast ("Saved X") does not say when edits made meanwhile are
  still unsaved. The dirty dot does say it.
- A board left mid-save moves to the top of the recent list when its copy is
  rewritten, since `savedAt` orders the list. That is consistent with "last
  write", but it can put it above the board on screen.

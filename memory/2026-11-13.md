# 2026-11-13 — Missing quick-switch numbers (investigation)

Branch `claude/festive-lamport-c061es`, at 4877602 (PR #16 merged).
**No code change.**

## The report

> Why am I not seeing the workspace switching icons?

The screenshot shows a board, "Coffee World", with two workspaces ("Workspace 1",
1 element; "Coffee Growing", 2 elements). The switcher menu is open. No numbers
show beside the switcher, and "Edited just now" sits right after it, whole.

## What was checked

- `main` has the feature (f479cc7), and its committed `index.html` contains the
  strip. A rebuild differs only by a CRLF inside the Drive multipart template.
- GitHub Pages deployed 4877602 on 2026-11-11 at 13:19 UTC, run 32, success.
- Build stamps (`window.mindflow.builtAt`):
  - before the feature (b7b921c): `2026-11-10T23:28:17Z`
  - with it (4877602): `2026-11-11T07:54:37Z`
- Chromium, with the user's names, all with the strip showing:
  - 91 combinations of width (1100–1920) and scale factor (0.67–3), which is
    how Chrome applies browser zoom.
  - The UI flow: rename the board, add from the menu, Escape, Page Up.
  - A two-workspace file dropped on the page, at 1280, 1512 and 1920.
- Shrinking the window from 1000 to 770 in 5px steps: the numbers are hidden
  only while "Edited" is cut short. No width hides the numbers with the label
  whole, which is what the screenshot shows. So the screenshot is not the
  current build's fit, in Chromium at least.

## Conclusion

Most likely the page predates the feature:
- a tab opened before the deploy and never reloaded, or
- a downloaded `index.html` from before 11 Nov.

Asked the user to run `mindflow.builtAt` in the console to confirm.

## Not verified

- **Safari and Firefox.** Only Chromium is in this container.
- **A stale fit (possible bug, not seen).** `WorkspaceNumbers.fit` runs only
  when the list changes or the bar resizes. If the numbers were dropped while
  the bar was tight, and then the board is renamed shorter, nothing refits them.
  This only matters near the threshold. It cannot produce the screenshot,
  because the label would still be cut short there.

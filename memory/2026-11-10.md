# 2026-11-10 — Workspaces within a file: UI ideas and a plan

Branch `claude/confident-newton-gro5wn`, on top of bd0e3d8. **Planning only.
No source, format or docs change.** Only `PROMPT.md` and this file changed.

## The ask

Several independent "workspaces" inside one board file. A file starts with a
default workspace, a new one is an empty environment, and going back to an old
one restores its work. The user wanted visual UI ideas first, then a plan
artifact.

## What was made

- **UI ideas (design canvas):** https://claude.ai/artifact/PtiE9Nhxhso9Tj1TVn1ZUH
  Four directions, each at desktop and phone size, drawn over the real top bar
  and tool palette (cut from the built `index.html` with Playwright):
  A tab strip, B top-bar switcher, C thumbnail panel, D floating pill.
- **The plan:** https://claude.ai/artifact/P8buPB26C7zEYfobqYDVCu

Both are private claude.ai artifacts, so they are not in the repo.

## Decisions the user made

- **Switcher: B**, a button beside the board name that opens a list styled like
  the recent-boards menu.
- **Undo: per workspace.** Undo only changes the workspace on screen.
- **Phone top bar: icon-only switcher below 760px** (answered in a comment on
  the plan). The board name keeps its place. The text button that takes the
  board name's place, as drawn in the phone mockup, is left for when the phone
  bar is reworked.

## What the plan proposes (not yet agreed)

- **Format 2.0.0.** `workspaces[]` of `{id, name, canvas, viewport, elements,
  meta}` plus `activeWorkspaceId` replace the top-level `canvas`, `viewport`
  and `elements`. `files` and `meta` stay board-level. Migration from 1.6.3
  wraps the drawing into one workspace with the fixed id `ws_1`.
  - Major, by the changelog's own rule: within a major version a newer file
    never uses anything an older reader lacks a rule for. A 1.6 build writes
    back only the top-level fields it knows, so it would drop extra workspaces.
  - Rejected: top level as the first workspace plus a list (1.7.0, lopsided and
    silently lossy in old builds), and a flat element list with `workspaceId`
    (old readers would draw every workspace on top of the others).
- **Store: one workspace on stage, the rest parked.** `state.document` stays
  the flat shape every drawing module reads, so the renderer, hit-testing,
  commands and exporters do not change. `store.history` becomes a getter for
  the staged workspace's history. `documentForSave()` becomes `boardForSave()`.
- **Switching is not an edit** (like a pan). Add, rename, move, duplicate and
  delete are edits but are on no undo stack. Delete asks when there is content.
- **Background and grid per workspace.** A new workspace copies the current
  one's.
- **Four phases:** format read/write, store operations, the switcher, then
  reach (PDF of all workspaces, find across workspaces).

## Found while reading the code (must be handled in phase 1)

- `Autosave.write` deletes a board's copy when
  `document.elements.length + preserved.length === 0`, and `app.ts:519` uses
  the same count before asking about unsaved work. With workspaces both must
  count every workspace, or a board whose active workspace is empty (right
  after "New workspace") loses its recovery copy.
- `validateDocument` reports unreferenced `files` from one element list. It
  must count references board-wide.
- `ImageCache.prune` is only a bitmap cache, so pruning by the staged elements
  costs a re-decode, not data.
- A 1.6 build opening a 2.0.0 file warns, finds no top-level `elements` and
  shows an empty board. Shipped builds cannot be changed.

- **The top bar overlaps badly at phone width.** At 390px the centre and right
  button groups draw on top of each other. The 2026-11-07 note recorded it for
  724–790px, and it is worse below that. Suggested as a separate task.
- `node_modules` is not installed in a fresh cloud container, so `npm test`
  and `npm run icons` need `npm install` first. The built `index.html` and the
  pre-installed Playwright were enough for this session.

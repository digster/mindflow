# 2026-08-26 — Colour support, and a real icon set

Two commits on `claude/colour-and-lucide-icons`. Neither changes the save format:
no `schemaVersion` bump, no migration, no new schema file, no `docs/CHANGELOG.md`
entry.

## Commit 1 — colour

The format had been colour-complete since 1.0.0. The UI exposed two of its colour
fields. `PALETTE.canvas` had existed since the first commit and was referenced by
**nothing** — a board could carry a coloured background that MindFlow rendered
faithfully and had no way to produce.

Closed the gap: text colour, table header fill, board background, and a picker
popover (palette + recent colours + hex) replacing the bare `<input type="color">`
at the end of each swatch row.

### The decisions worth remembering

**Text colour is one control over two storage shapes.** A type with
`capabilities.text` stores `color` on the element; every other shape stores it on
`label`. `Actions.setTextProperty` already routed both ways, so the control
needed no per-type code — only the *read* half (`textColorOf`) had to learn the
split, and it stays in the style panel because marking a swatch active is a
display concern, not a model one.

**Per-type palettes went on the registry, not in a branch.** A sticky note should
offer the paper tones it is actually created with. The obvious fix was
`type === 'sticky'` in the style panel; instead `ElementDefinition` gained an
optional `palette`. Optional means no existing shape module changed and the
contract test's capability assertion was unaffected — the same shape as
`textRegions` and `interiorHandles`.

**Board background is in the top bar, not the style panel.** The panel is the
obvious home and is wrong: `test/e2e/board.spec.ts` asserts it is hidden whenever
the selection is empty, which is exactly when you reach for the background. The
assertion was worth more than the placement.

### The bug this uncovered

Dragging inside the existing `<input type="color">` pushed **one undo entry per
frame**. It had shipped with the original swatch row and nothing caught it —
every proxy was true: the element changed, the board went dirty, the undo button
enabled.

`coalesce` had been a parameter on `updateElements` since the beginning;
`restyle` simply never passed it. But threading it through the preview path alone
is only half a fix: if the drag's *final* value then goes through a separate
non-coalescing commit, the gesture costs **two** undos and the first rewinds only
the last pixel of movement — which looks like it works, and is arguably worse.
A drag is one gesture from first frame to last, `input` and `change` alike. That
model was already in `input/controller.ts`; the picker just had to adopt it.

The test asserts the user-visible property — *one undo returns to where the drag
started* — not the size of the history stack, which would have passed the broken
version.

## Commit 2 — Lucide icons

`src/ui/icons.ts` was 46 hand-written paths, on the reasoning that a dependency
would have to be either CDN-fetched (impossible: zero external requests) or
bundled whole. That missed the third option: extract at **build** time from a
devDependency and commit the result.

`scripts/build-icons.mjs` + `npm run icons`. The manifest lives in the script, so
adding an icon is one line. Output committed, like `index.html`, with a unit test
that regenerates it in memory and fails on drift.

`icon()` in `dom.ts` now takes inner markup and sets `innerHTML`, because real
icons draw from several elements — the old single-`<path>` construction could not
express a `<rect>` plus two `<path>`s. The `innerHTML` is justified by the
generator's whitelist, which is why the test asserts on the extractor's
*refusals* rather than only its output.

### The bug this uncovered

The whitelist dropped what it did not recognise instead of throwing. The
attribute-name pattern was `[a-z-]+`, which cannot match `x1`/`y1`/`x2`/`y2`, so
every `<line>` lost its coordinates — the `frame` icon generated as four empty
`<line />` elements, drawing nothing. Found by adding "assert nothing is left
over after parsing", which was itself only added because a *security* test
(`<foreignObject />` must be refused) forced the tag pattern wider.

Also: Lucide names alignment icons after the axis of the rule, not the direction
of travel — `align-start-vertical` is align-**left**. Six of the eight are named
this way. The tests assert against geometry (`alignLeft` has a rule at `x=2`) so a
future swap cannot transpose them.

`drive` maps to `cloud`: Lucide dropped brand marks for trademark reasons, and
approximating Google's is worse than being generic.

## Verification

`npm run typecheck`, 354 unit tests, 106 e2e, `npm run build` — all green. Both
the style panel and the top bar were checked in a real browser; every icon
renders (asserted: zero empty `<svg>` elements).

## Not done

and unrelated to `lucide-static`. `audit fix --force` wants a breaking vitest
upgrade, so it was left alone.

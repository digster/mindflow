# 2026-09-29 — PDF export: one page per frame

Branch `claude/intelligent-rubin-fs62us`, on top of 6e3725f. No format change,
so no schema, CHANGELOG or version bump.

## The ask

"Add a new export option where every frame of the board will be fit in a new
page of the export PDF. The contents of the frame should be auto-adjusted
automatically based on the PDF page."

## What changed

- **Export dialog** (`showExportDialog`, now takes an options object): a fourth
  format, *PDF — one page per frame*. Its rows are page size (A4 default, A3,
  US Letter, US Legal) and orientation (Auto default, Portrait, Landscape),
  side by side in a `.mf-field-pair` that wraps on a phone, plus resolution
  (150 or 300 dpi, 300 default). A live hint reads "3 frames → 3 pages, in
  reading order…". With no frames it explains how to add one and Export is
  disabled. *Selection only* means the selected frames. It is disabled and
  cleared for a PDF when no frame is selected, and the user's choice comes back
  on switching format.
- **Palette**: "Export frames as PDF…" (`file.exportPdf`) opens the dialog on
  PDF. `buildCommands` extras gained `onExportPdf`.
- **`render/pdfLayout.ts`** (pure, published): `readingOrder` (rows anchored by
  their first frame; a frame joins if its top is above the anchor's midline),
  `pageContentBox` (frame plus half its stroke), `fitToPage` (uniform scale into
  a 36pt margin, centred; auto keeps the larger scale, and a tie keeps
  portrait), `rasterSize` (dpi, capped at 16,000px a side and 4096² area).
- **`render/pdfWriter.ts`** (pure): PDF 1.4. Per page, a page, a content stream
  and a FlateDecode DeviceRGB image. Also bookmarks (`/Fit`), an Info title
  (UTF-16BE hex) and `/DisplayDocTitle`. Returns chunks for a Blob.
  `deflate` = `CompressionStream('deflate')` (zlib, exactly what FlateDecode
  reads). `rgbaToRgb`. A `Bytes` alias for `Uint8Array<ArrayBuffer>`.
- **`render/exportPdf.ts`**: glue, with one reused canvas (`alpha: false`)
  shrunk to 0×0 afterwards. It paints white, then the board background unless
  transparent, then the page contents. A missing `CompressionStream` gives a
  clear error.
- **`model/frames.ts` `frameContents`**: a frame's page is the frame, its
  members, and any element in no frame (null or dangling `frameId`) whose
  centre is inside it. `frameFor` now shares `frameContaining`.
- **`render/export.ts` `paintElements`**: the shared PNG/PDF paint loop. It
  applies the frame clip like `Renderer.paintElement`.
- `app.ts` `exportBoard(format?)`: counts visible frames and handles `pdf`.
  Toasts "Exporting N pages…" only if the export takes longer than 400 ms, then
  "Exported N pages.".

## Bugs found on the way

1. **PNG export never clipped frame members** (the docs say every renderer
   does). Fixed by the shared paint loop. An e2e test failed on the old build.
2. **`.mf-field { display: flex }` beat `[hidden]`**, so the dialog's PNG
   Resolution row showed for SVG and JSON. Added `.mf-form[hidden],
   .mf-field[hidden]`. Confirmed on the old build in Chromium, and an e2e
   test failed there.
3. **Arrows, lines, text and freehand drawn in a frame are never enrolled**
   (`finishLinearCreate`, `finishFreehand` and `createTextAt` skip
   `reassignFrames`). First seen as missing arrows and text in a real PDF.
   *Not fixed* on the board, since that changes board behaviour beyond this
   request. The PDF is protected by `frameContents`' geometric fallback.
   Suggested as a follow-up task.

# Later the same day — frame membership of new elements (commit 1 of 2)

The ask: "for the second image, work on it" (the enrolment bug noted above),
and "ship our own fonts" as a separate commit.

## What changed

- `enrolInFrames(document, added)` in `model/frames.ts`. Each added element
  goes in the topmost visible frame containing its centre, and frames in none.
  The frames being added are candidates too, sorted by `zIndex`, so pasted
  contents join the pasted frame. Unchanged elements are returned as the same
  object.
- Called before `addElements` at every non-transient adding path:
  `finishCreate`, `finishLinearCreate`, `finishFreehand` and `createTextAt`
  (controller), `paste` and `duplicate` (actions), and `insertImageFile` (app).
- `finishCreate` no longer runs a second "Reframe" command, so drawing a shape
  in a frame is one undo step (it was two).
- `frameContents`' geometric fallback stays, for older boards and script-written
  files.

## Bugs confirmed first (in the browser, on the old build)

- Line, arrow, freehand, text and pasted image in a frame: `frameId` null. The
  arrow did not move with the frame.
- Rectangle in a frame: the first undo only un-enrolled it.
- Duplicate or Ctrl+V of a frame with its member: the copy's member pointed at
  the original frame, and was clipped to it.

## Tests

- Unit `enrolInFrames` (+7): lands in, pasted away leaves, pasted frame claims
  pasted contents, topmost counts added frames, frames never nest, hidden
  frames ignored, identity kept.
- E2E `frame membership of new elements` (9): line, arrow, freehand, text,
  arrow moves with frame, pasted image, one undo step, duplicate, Ctrl+V. All 9
  failed on the old build for the expected reasons.
- "Paste here" from the context menu cannot be e2e-tested: it reads the system
  clipboard, which hangs headless Chromium on file://. The "lands outside every
  frame" case is covered by the unit test.

## Docs

`docs/05-interactions.md` Frames and `docs/03-elements.md` Membership (applied
on draw, paste, duplicate and insert as well as drop), `CLAUDE.md` row,
`LEARNINGS.md` entry rewritten ("Every path that adds an element must enrol
it").

# Later the same day — bundled fonts and real PDF text (commit 2 of 2, format 1.6.2)

The ask: "can we ship our own fonts so that we dont rely on the system fonts?"
It answered the note that PDF text could not be selectable because a page
cannot read the system fonts the canvas measured with.

## Fonts

- `scripts/build-fonts.py` (`npm run fonts`, fontTools 4.66.1 under uv) reads
  the `@expo-google-fonts/{inter,noto-serif,jetbrains-mono,kalam}`
  devDependencies. For each face it keeps a Latin subset (Basic Latin,
  Latin-1, Latin Extended-A, punctuation, arrows and symbols), drops GSUB,
  GPOS, GDEF, kern and hinting, and keeps timestamps (deterministic). It writes
  `src/fonts/{family}-{regular,bold}.ttf` (24–42 kB each) and `LICENSES.md`.
  All four are OFL with no Reserved Font Name.
- Faces: sans Inter 400/600, serif Noto Serif 400/600, mono JetBrains Mono
  400/600, hand Kalam 400/700. Kalam was chosen over Caveat for legibility at
  20px (checked on a rendered specimen). The specimen also showed the old
  `hand` stack rendering as a Times-like serif in this container.
- Measured first: with those tables stripped, canvas `measureText` equals
  Σ advances × size / upem to within 0.0025 px for all four, 9–72px. That is
  the basis of everything below.
- `build.mjs` `fontPlugin`: `.ttf` imports become base64 of zlib-deflated
  bytes (typed by `src/fonts/fonts.d.ts`). index.html grew from 225 kB to
  about 412 kB.
- `render/fonts.ts`: `installBundledFonts` (inflate with DecompressionStream,
  then `new FontFace(name, bytes, {weight: '1 549' | '550 1000'})`; never
  rejects), `bundledFontsReady`, `bundledFace(family, weight)`, and
  `fontFaceRule` (a data-URI @font-face for SVG). `main.ts` awaits it before
  constructing the app. Boot was about 115 ms in the probe.
- `shared.ts`: `BUNDLED_FAMILIES` ("MindFlow Sans"…), `FONT_STACKS` lead with
  them, `BOLD_FACE_WEIGHT` = 550, `faceRole`.
- `render/ttf.ts`: pure reader for cmap 4/12, hmtx, head, hhea, maxp, OS/2,
  post and name, plus `textAdvance`.

## PDF text

- `drawTextBlock` offers each block to a `TextSink` registered per context
  (`setTextSink`, a WeakMap). The sink sees the lines with their x, baseline
  and width, the box, the top and bottom, and the font; `ctx` carries the
  transform, fill and alpha.
- `render/pdfText.ts` `planText`: null if any character is missing from the
  face (pixels only). `text` if the lines fit their box, the ink is inside the
  frame, and no later element's box overlaps it. Otherwise `hidden` (pixels
  plus invisible text, Tr 3). Also `composeMatrix` and `parseCanvasColor`.
- `paintElements` gained `beforeEach(element, index)` so the sink knows what
  is painted later.
- `pdfWriter.ts`: `PdfFont`, `PdfTextBlock`, and `PdfPage.text`. Fonts are
  embedded once per document as Type0/Identity-H over a CIDFontType2 with
  FontFile2 (the zlib bytes as they are, with `/Length1`), `/W` for the used
  glyphs, and a ToUnicode CMap; ExtGState `/ca` for alpha. Matrix numbers get
  5 decimals.
- Without the fonts installed, pages are pictures only.
- Verified: MuPDF (no repair, spans in Inter, covered note has alpha 0,
  Cyrillic absent), pypdf strict (extract_text, CIDFontType2, FontFile2 24,964
  bytes). Text ink sits within 1 px of the canvas's at 1 px per scene unit
  (bbox (13,13)–(186,64) vs (13,12)–(186,63) inside the note).

## SVG

`exportToSVG` records the faces its text uses (`usedFaces`, set for one
synchronous call) and inlines them as `@font-face` data URIs in `<defs><style>`.

## Format 1.6.2

New schema file (version strings only), an identity migration 1.6.1 → 1.6.2
with a test, `CURRENT_SCHEMA_VERSION`, and a CHANGELOG entry with the

## Tests

- Unit: `ttf.test.ts` (10, against fontTools values), `pdfText.test.ts` (11),
  `pdfWriter.test.ts` (+7 text/font), `document.test.ts` (+1 migration).
- E2E: new `fonts.spec.ts` (12): all faces installed; canvas equals the
  advance sums for each of 8 faces (<0.01 px); the 550 rule at 100–900; SVG
  embeds exactly the face used; boots without DecompressionStream.
  `export.spec.ts` PDF text (4): real text decoded through ToUnicode and

  only without fonts. `seed` now stacks on the existing board.
- The existing suite passed unchanged with the new fonts: nothing depended on
  system-font metrics.

## Noticed, not changed

- Text boxes in existing boards were sized with the author's system font. With
  the new faces, an auto-width text element may be a little wider or narrower
  than its box until edited. This is the same kind of mismatch boards already
  had between Mac and Windows.
- Characters outside the Latin subsets still fall back to system fonts (not
  reproducible, and pixels only in a PDF). Adding Greek or Cyrillic means
  bigger faces; Kalam has no Cyrillic.

# 2026-09-22 — Shapes, and making a finger a first-class pointer

Branch `claude/3d-shapes-touch-fixes-pl2xsg`. Four commits: one feature, two
bug fixes that were asked for, and one gap the second fix made impossible to
ignore. Schema **1.3.0 → 1.4.0**.

## The ask

> - add some basic 3d shapes
> - while working with a touch device like an ipad, if the cursor in the text
>   box is active and i click elsewhere or select something else, the cursor is
>   still active.
> - Also, the text box selecting and dragging does not seem to work well(on
>   touch devices).
> - do the 3 changes in different commits

Scoped in conversation to thirteen types rather than three, reached through a
flyout rather than thirteen toolbar buttons, plus a fourth commit for pinch and
two-finger pan.

## Commit 1 — thirteen element types

Five flat polygons (`triangle`, `pentagon`, `hexagon`, `star`,
`parallelogram`) and eight solids (`cube`, `cylinder`, `cone`, `pyramid`,
`sphere`, `prism`, `torus`, `capsule`).

**None of them adds a field.** That is the whole design. A polygon's vertices
are fractions of its box; a solid's depth is `0.25 × min(w, h)`, computed. A
stored `depth` is the same mistake absolute table track lengths would have been
— a second description of how big the shape is, which then has to be kept in
step with `width`/`height` on every resize, meaning a type-specific rule inside
`input/transform.ts`, which is forbidden from knowing what a cube is. Computed,
a cube's JSON is a rectangle's JSON with a different `type`.

Three more decisions worth keeping:

**All geometry is inscribed in the box.** A cube's front face is inset by `d`
rather than the projection hanging outside the box. Otherwise `width`/`height`
describe something smaller than what is drawn and every reader that culls,
hit-tests or measures a board inherits the discrepancy.

**One fill, three tones.** Lit and shaded faces are derived per sRGB channel
(±15%), and a fill that will not parse as hex is used unchanged everywhere — a
published fallback, because two renderers guessing tones in different colour
spaces is how they come to disagree about one file.

**Polygons are fitted to the box, not kept regular.** A pentagon in a 300×80 box
is wide and flat, exactly as an ellipse is.

### Two things that fell out

`labelBox` on the registry. A solid's label belongs on its front face, and a
`ctx.translate` inside `draw` moves only one of the **three** readers of that
box — the canvas, the DOM text editor and the SVG exporter each place it
independently. Optional, so no existing type changed.

The tool list stopped being four hand-maintained copies. `SHAPE_TOOLS` in the
store now feeds the flyout, the command palette and the controller; `commands.ts`
carried a comment about exactly the drift that costs (diamond and frame were
missing from the palette for two releases).

### The bug this uncovered

A sampled arc misses the points where the curve is tangent to its box, so a
cylinder's silhouette fell 0.1 units short of its own bounding box. Rounding the
segment count up to a multiple of four puts a sample on the arc's midpoint and on
every quadrant point. Spacing describes smoothness; it says nothing about extent,
and extent is what culling and snapping read.

## Commit 2 — the caret that would not go away

`controller.ts` carried a comment saying a canvas press committed the editor and
only cleared a store flag nothing listens to. The editor really closed as a side
effect of the browser moving focus out of the textarea — a mouse convention. On
iPadOS, over a `touch-action: none` canvas holding a pointer capture, a tap does
not reliably move focus, so the caret survived. Clearing the flag also
desynchronised it from the editor, so the *next* tap started a gesture underneath
a live editor.

The editor now closes itself: an explicit commit from the controller, a
window-level `pointerdown` listener for the chrome (which had no commit path at
all), and a `blur()` before hiding so the soft keyboard goes down. `open()`
focuses synchronously so it comes back up — iOS raises it only inside the
gesture.

Two traps: the listener has to be registered a **task** later, or the press that
opened the editor dismisses it (a microtask is not enough — the dispatcher drains
the queue between listeners); and focusing inside the gesture loses the focus to
the compatibility `mousedown` unless that one press prevents its default.

`app.ts` had already worked around this class of bug for "New board" and for
loading a file, with a comment explaining exactly why blur cannot be trusted. The
general case was simply never done.

## Commit 3 — every input constant was sized for a mouse

3px drag threshold (below a finger's wander during a stationary tap — and since
a gesture recomputes from its origin, the element jumped the whole distance),
8px click tolerance, 9.5px handle radius. All now read from
`event.pointerType`, recorded at pointerdown: touch gets 8, 16 and 11.

Keyed off the gesture rather than the device deliberately — a tablet with a
stylus wants the precise numbers.

`pointercancel` was not a teardown. It leaked the pointer capture (whose symptom
is delayed and looks unrelated: the *next* drag silently does nothing — already
in LEARNINGS.md) and left transient edits in place, so an interrupted drag moved
an element with no undo entry and an interrupted creation left a shape undo could
not remove. Rare with a mouse; routine with a finger.

Double tap opens the text editor, since `dblclick` is synthesised from
compatibility click pairs a touchscreen does not reliably produce — and it was
the *only* route into editing an existing element. Long press opens the context
menu, which the mid-gesture bail had been swallowing every time.

## Commit 4 — pan and pinch

Not asked for, and the previous commit made it impossible to leave: the canvas
sets `touch-action: none`, so nothing pans or zooms unless the app does it, and
a touchscreen could only zoom through the toolbar.

A second finger abandons the first finger's gesture (rewinding, not committing —
the user was reaching to zoom) and starts a pinch that recomputes from the
captured start like everything else. The arithmetic is a pure function in
`input/pinch.ts` because Playwright drives two contacts only through raw CDP.

## Testing

403 unit/contract (was 354) and 135 e2e (was 106). A second Playwright project
with a real touchscreen, driven through `Input.dispatchTouchEvent`.

**The touch tests initially passed against the broken code**, because Chromium's
touch emulation still sends the compatibility mouse events that blur the
textarea. They now suppress the focus change explicitly, which is the part of
iPadOS that cannot be emulated — and three of them fail without the fix, as
checked by reverting it.

## Not done, deliberately

- **Solids have no hand-drawn form.** A rough outline is one closed polygon; a
  cube's interior edges cannot survive that. Stated in the changelog.
- **No per-face styling and no stored depth.** `meta` is the escape hatch.
- **Handles still beat elements**, now with a fatter touch slop. Changing that
  precedence is a behaviour change well beyond these bugs.

# 2026-09-22 (later) — Retiring four solids, and a collapsible style panel

Branch `claude/compassionate-euler-a8x9p5`. Two commits, one per ask.

## Commit 1 — retire `sphere`, `prism`, `torus`, `capsule` (schema 1.5.0)

**Retired from the format, not hidden in the UI.** Hiding them would have left
four types specified, validated and drawn forever for boards that could only
come from one release. So: new immutable `mindflow-1.5.0.schema.json`, types,
registry, `SHAPE_TOOLS`, icon manifest, export cases, docs sections and matrix
rows all gone. `cube`, `cylinder`, `cone`, `pyramid` are unchanged.

**The migration is the important part.** An unknown type is *preserved but not
drawn*, so without one a 1.4.0 board would open with the shapes silently
missing. 1.4.0 → 1.5.0 is the first non-identity migration: each retired solid
becomes the flat shape that draws its silhouette — sphere and torus → `ellipse`,
prism → `triangle`, capsule → `rectangle` with `cornerRadius = min(w, h) / 2`
(which is exactly a stadium). Ids are kept, so bound connectors stay bound.
`style.roughness` is zeroed on converted elements: solids never drew it, the
flat shapes do, and carrying it over would make them go sketchy on upgrade.

Keyed on declared version, so a board *claiming* 1.5.0 with a `torus` in it is
treated as an unknown type (preserved), not reinterpreted.

**Minor, not major** — by the changelog's own table, major means old readers
can't read new files; every 1.5.0 file is a valid 1.4.0 file. Added a table row
and reworded "additive within a major version" to match.

The torus was the only user of `SolidFace.hole` and the `fillRule` parameter on
`paintPath`/`paintFace`, plus the even-odd SVG branch — all removed rather than
left as dead generality.

### Gaps this exposed

- `contract.test.ts` checked registered types → docs, never docs → registry. A
  removed type's docs would have passed. It now checks the capability matrix in
  both directions, and has a migration fixture validating a converted 1.4.0
  board against the current schema.
- `shapes.mindflow.json` (a 1.4.0 example) had to drop the four: examples
  validate against the *current* schema. `docs/README.md` now says so.
- `06-persistence.md` still said "no migrations yet", and both it and
  `migrate.ts` pointed at a `test/unit/migrate.test.ts` that has never existed
  (migration tests live in `document.test.ts`). Fixed in passing.
- Added a "Retiring a type" checklist to `docs/09-extending.md`.

### Environment note

The pinned `@playwright/test` wants `chromium_headless_shell-1234`; this
container ships `-1194`. The e2e suite was run through a scratchpad config that
spreads `playwright.config.ts` and sets `launchOptions.executablePath` to
`/opt/pw-browsers/chromium`. The repo config was not changed.

## Commit 2 — a collapsible style panel

The panel is now `aside > header (title + toggle) + body`. Only the body is
rebuilt by `sync()`; the header persists, which is what keeps keyboard focus on
the toggle across presses (a rebuilt button drops focus to the page — asserted).

- **Collapsed = the toggle alone.** `is-collapsed` hides the body and title and
  sets `width: auto`; on the ≤760px bottom-sheet layout it also drops `left`, so
  the button sits bottom-right above the tool rail.
- **Remembered per browser** under `mindflow.stylePanelCollapsed`, guarded like
  every other `localStorage` access. Not per board: it is about the screen.
- **Nothing is built while collapsed.** `sync()` runs on every document change,
  drag frames included, so a closed panel now costs nothing.
- **`Cmd`/`Ctrl` + `\`** (the chord design tools use for "hide panels", unclaimed
  by browsers) and a palette command, both no-ops with nothing selected — the
  palette greys it out, `toggleCollapsed()` returns early. Flipping a preference
  with no panel on screen would only surprise the user later.
- **Hugs its content** (`max-height` instead of `top` + `bottom`). Not strictly
  asked for, but the old panel covered the board to the bottom edge even for a
  six-row selection, which is the same complaint.
- 40px toggle under `(pointer: coarse)`; `aria-expanded` + `aria-controls`.

### Testing

Six e2e tests in `board.spec.ts` and one in `touch.spec.ts`. The touch one is
the real claim: with the panel open, `elementFromPoint` over a sticky beneath it
is the panel; after a finger taps the toggle it is the canvas, and a tap there
selects the sticky — without the toggle tap having disturbed the selection.

The reload test first polls IndexedDB until the autosave record exists: the
recovery dialog on reload otherwise races the 1.2s autosave debounce. The probe
aborts `onupgradeneeded` so it can never create a store-less database under the
app.

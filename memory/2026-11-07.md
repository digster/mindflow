# 2026-11-07 — "Edited 5 minutes ago" beside the board name

On `main` at 340f87d, uncommitted. No format change, so no schema, CHANGELOG or
version bump: files are written exactly as before.

## The ask

"display the last edit date for a file beside its name in the main toolbar."

## Decisions

- **The time is `meta.updatedAt`.** It is in the format and already moved by
  `applyCommand` on every command. It works for every source: new, file, Drive,
  recent copy. A file handle's `lastModified` would not have covered all of
  those.
- **Relative wording, absolute on hover.** It reuses the recent-boards menu's
  `formatRelativeTime`, moved to the new `src/ui/time.ts`: *Edited just now*,
  *5 minutes ago*, *yesterday*, then a date. The tooltip uses
  `toLocaleString(dateStyle: medium, timeStyle: short)`. A `<time datetime>`
  element, not a live region.
- **"Created …" when `updatedAt <= createdAt`.** A new board has equal stamps,
  and *Edited just now* on a blank board claims an edit that never happened.
- **The timer fires when the wording changes** (`relativeTimeChangesIn`),
  capped at 60 s, because timers stop during sleep.

## Two bugs found while building it (fixed)

1. **Autosave re-stamped `updatedAt` on every open.** `serializeDocument`
   writes now, and autosave writes a copy on `load`. From the second reopen on,
   a board read as edited when it was last opened. Fix:
   `SerializeOptions.stampUpdatedAt`, which is false for autosave only. Side
   effect: autosave's identical-write skip can now match (it never could). The
   `06-persistence` claim that undo/redo round trips are skipped was false
   before and still is. Corrected.
2. **An abandoned text box moved the time.** The transient add and delete each
   bump `updatedAt`. `DirtyCheckpoint` now holds `updatedAt`, and `restoreDirty`
   puts it back, replacing the document object but not `elements`. It emits
   once.

## Layout

- **The name field fits its text.** The `<input>` and a hidden copy of the
  text (`.mf-board-name-sizer`) share an inline-grid cell, so the label sits
  right after the name. Before, the field was a fixed box of about 180px, and
  the label floated far from a short name. `size="1"` is a guard. Chromium
  ignores the default width under `width: 100%` anyway, as found by mutation.
  `text-overflow: ellipsis` on the input.
- **Above 760px, the button groups have `flex-shrink: 0`**, so the label gives
  way first (`flex-shrink: 100`, ellipsis), then the name. Without this, a long
  name plus the label made the icons overlap at 900px.
- **Below 760px:** the label is `display: none`, and the field keeps the old
  fixed 140px box. A fitted field has no slack, and it clipped "Untitled board"
  at 724px.

# Follow-up — saves keep the edit time too (format 1.6.3)

The user chose to make saves keep the board's own `updatedAt` as well. Before,
a board edited at 10:00 and saved at 10:30 read 10:00 in the session and 10:30
once reopened.

## Why a patch (1.6.3), not no bump or a major bump

- **Not "no bump".** 1.6.1 and 1.6.2 each bumped the patch version for a
  behaviour change with no structural one. The version also tells a reader
  which meaning `updatedAt` has.
- **Not major.** The CHANGELOG table lists "changing a field's meaning" as
  major. But the value is still a time the board was up to date, a 1.6.2
  reader is not misled in any way that matters, and an old file cannot be
  migrated to anything better. The CHANGELOG entry argues this.

## What changed

- **`serializeDocument`** writes `document.meta.updatedAt`. The
  `SerializeOptions.stampUpdatedAt` option from earlier today is gone, since
  nothing stamps any more. Autosave calls it plainly.
- **Loader:** a missing or unreadable `updatedAt` defaults to `createdAt`, not
  to now. A default of now would be saved back as a phantom edit.
- **The version:**
  - `CURRENT_SCHEMA_VERSION` is `1.6.3`.
  - New `docs/schema/mindflow-1.6.3.schema.json`: a copy of 1.6.2 with `$id`,
    the description, and descriptions for `createdAt` and `updatedAt`.
  - An identity migration from `1.6.2`.
  - `docs/README.md` now links the new schema.
- **`DocumentMeta.updatedAt`** has a doc comment.
- **Docs:**
  - `02` (the `meta` table, a new paragraph on `updatedAt` and its loader
    default, and the canonical-output bullet)
  - `05` and `06` (no more "a save stamps it")
  - `CHANGELOG` 1.6.3
  - ARCHITECTURE, CLAUDE.md row, README, LEARNINGS.

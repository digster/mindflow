# 2026-08-16 — A New board button for the top bar

## Context

The session started as a question — how do you create a new blank board? — and
the answer exposed a gap. `Cmd/Ctrl + N` was the only path, and it is the one
shortcut browsers reserve for themselves.

## What was wrong

1. **The top bar had no New button.** `ToolbarCallbacks.onNew` was declared
   (`src/ui/toolbar.ts`) and `Application` passed a bound `newBoard()`
   (`src/app/app.ts`), but `buildTopBar()` never rendered a control that called
   it. A fully wired seam with no call site.
2. **The only binding was unreachable.** `Cmd`/`Ctrl` + `N` is claimed by Chrome,
   Safari and Firefox for "new window"; the keydown is consumed by the browser
   chrome before the page sees it, so `preventDefault()` never gets to run. In an
   ordinary tab the feature was effectively unreachable without reloading the
   page and declining autosave recovery.

## What changed

- `src/ui/icons.ts` — a `newBoard` icon: dog-eared page with a plus, in the same
  hand-written 24×24 stroke style as the rest.
- `src/ui/toolbar.ts` — the button, first in the file group (New / Open / Save /
  Export / Drive). Its tooltip is plain `New board` with **no** shortcut hint —
  the one file button that omits one — because advertising a chord the browser
  eats would be a lie. The comment explains that, since the omission otherwise
  looks like an oversight.
- `src/input/keyboard.ts` — the handler stays (it does fire in installed and
  standalone windows) with a comment saying why it looks dead. The help dialog's
  entry now reads "New board — if the browser allows it; use the toolbar
  otherwise".
- `docs/05-interactions.md` — a note under the File shortcut table naming the
  limitation and pointing at the button.
- `LEARNINGS.md` — the reserved-chord trap, generalised: any file action bound to
  a reserved chord needs a visible control or it does not exist.
- `.gitignore` — `.playwright-mcp/`, a backstop against leaked screenshots.

## Tests

Four new e2e cases in `test/e2e/board.spec.ts` under `new board`: the button is
present; a dirty board resets after confirming the discard; cancelling keeps the
board; a clean board skips the prompt entirely.

The reset test asserts the **board id changes**, not just that `elements` is
empty. That is the assertion with teeth — clearing elements without minting a new
identity would leave the board pointed at its old Drive file and silently
overwrite it on the next save.

191 unit/contract and 34 e2e tests pass; typecheck clean; `index.html` rebuilt
and committed alongside the source.

## Not done

No format change, so no schema version bump, no `docs/CHANGELOG.md` entry, no
migration. The README's shortcut table was left alone — it never listed `Cmd+N`,
which turns out to have been right.

# 2026-08-16 — A New board button for the top bar

## Context

The session started as a question — how do you create a new blank board? — and
the answer exposed a gap. `Cmd/Ctrl + N` was the only path, and it is the one
shortcut browsers reserve for themselves.

## What was wrong

1. **The top bar had no New button.** `ToolbarCallbacks.onNew` was declared
   (`src/ui/toolbar.ts`) and `Application` passed a bound `newBoard()`
   (`src/app/app.ts`), but `buildTopBar()` never rendered a control that called
   it. A fully wired seam with no call site.
2. **The only binding was unreachable.** `Cmd`/`Ctrl` + `N` is claimed by Chrome,
   Safari and Firefox for "new window"; the keydown is consumed by the browser
   chrome before the page sees it, so `preventDefault()` never gets to run. In an
   ordinary tab the feature was effectively unreachable without reloading the
   page and declining autosave recovery.

## What changed

- `src/ui/icons.ts` — a `newBoard` icon: dog-eared page with a plus, in the same
  hand-written 24×24 stroke style as the rest.
- `src/ui/toolbar.ts` — the button, first in the file group (New / Open / Save /
  Export / Drive). Its tooltip is plain `New board` with **no** shortcut hint —
  the one file button that omits one — because advertising a chord the browser
  eats would be a lie. The comment explains that, since the omission otherwise
  looks like an oversight.
- `src/input/keyboard.ts` — the handler stays (it does fire in installed and
  standalone windows) with a comment saying why it looks dead. The help dialog's
  entry now reads "New board — if the browser allows it; use the toolbar
  otherwise".
- `docs/05-interactions.md` — a note under the File shortcut table naming the
  limitation and pointing at the button.
- `LEARNINGS.md` — the reserved-chord trap, generalised: any file action bound to
  a reserved chord needs a visible control or it does not exist.
- `.gitignore` — `.playwright-mcp/`, a backstop against leaked screenshots.

## Tests

Five new e2e cases under `new board` (the button is present; a dirty board resets
after confirming; cancelling keeps the board; a clean board skips the prompt; an
open editor does not survive the reset) and two under `text editing` (a no-op
edit is not an edit; a real edit still commits).

The reset test asserts the **board id changes**, not just that `elements` is
empty. That is the assertion with teeth — clearing elements without minting a new
identity would leave the board pointed at its old Drive file and silently
overwrite it on the next save.

## The bug the button uncovered

Chasing "what happens if the editor is open when the board resets" found a real,
pre-existing defect that had nothing to do with the button.

**`TextEditor.commit` dirtied the board for edits that changed nothing.**
`Store.execute` recognises a no-op command by reference (`next === document`),
and `commit` always rebuilds the element — a structurally identical object with a
new identity. So double-clicking a shape and closing the editor without typing
marked the board dirty and pushed a phantom "Edit text" onto the undo stack. It
had always been reachable via `Cmd+O`; the New button just made it obvious.

Value comparison at commit time does **not** work as a guard: `onInput` has
already written every keystroke into the live document transiently, so the
element always matches the textarea by then. The fix is a `touched` flag set in
`onInput` and checked in `commit`.

The originally suspected bug — a floating editor left over the new blank board —
did **not** reproduce in Chromium, because clicking a button there moves focus
and the blur commits. It is still guarded against: whether a button takes focus
on click is a platform convention, and macOS browsers traditionally do not.
`newBoard` and `applyLoad` now close the editor explicitly rather than relying on
that side effect.

## Tally

191 unit/contract and 37 e2e tests pass; typecheck clean; `index.html` rebuilt
and committed alongside the source.

## Not done

No format change, so no schema version bump, no `docs/CHANGELOG.md` entry, no
migration. The README's shortcut table was left alone — it never listed `Cmd+N`,
which turns out to have been right.

Three edge cases around `newBoard` remain untested: a Drive save in flight when
the board resets, the image decode cache after a reset, and dismissing the
discard dialog with Escape rather than the button.

# 2026-08-16 (later) — Two feature batches, and schema 1.1.0 + 1.2.0

Started as "suggest the next features", became a plan, became an implementation.
Branch `claude/next-feature-suggestions-qvys76`.

## Batch 1 — making built things reachable

The theme: several capabilities existed and could not be invoked.

**`Actions.align` had no caller.** Not the style panel, not the keyboard, not a
menu. Exposing it meant fixing it first, because it was wrong in three ways
nothing had noticed:

| Defect | Cause |
|---|---|
| Moved locked elements | used `selectedElements()`, not `editableSelection()` |
| Tore groups apart | selection expands to whole groups, so members aligned onto each other |
| Misplaced rotated elements | rotation-aware bounds, then assignment using the *unrotated* box |

Units now translate by a delta derived from their world bounds, which makes
rotation and grouping fall out for free rather than needing cases. `distribute`
is new and equalises gaps rather than centres.

**Context menu.** `onContextMenu` already suppressed the browser menu and its
comment claimed "the app supplies its own menu" — it did not. Two details the
controller needed: refuse to open mid-gesture, and release the pointer capture
that `pointerdown` took *before* the right-button bail (otherwise the next
left-drag silently does nothing — there is a test for exactly that).

**`src/ui/popover.ts`** is the shared substrate for the menu, palette and find
bar. Every dialog in the app is a modal `<dialog>`, which is wrong for anything
anchored at the pointer.

**Command palette** (`Cmd+K`) renders `src/app/commands.ts`, one registry over
`Actions` plus the toolbar's own callbacks — now held as a field so there is not
a second copy to drift. It restores a keyboard route to New board, which `Cmd+N`
cannot provide.

**Find** (`Cmd+F`) with matching in `src/model/search.ts`, kept pure for the node
test environment.

**Style clipboard** copies appearance, routing typography between the two places
it lives. Needed a fix elsewhere to work at all — see LEARNINGS.

## Batch 2 — the format

Split into two versions deliberately, because published schemas are immutable and
`frame` was the item most likely to grow.

**1.1.0 — `diamond` + `roughness`.**

The prerequisite was an `outlineIntersect` registry member: auto-anchoring lived
in `geometry.ts` as `if (el.type === 'ellipse')`, the one place outside
`render/shapes/` breaking the no-branching rule. Adding a diamond would have
broken it twice.

`roughness` needed no new field. Jitter needs a seed; storing one would be a
structural change to every element for a value already present. **The seed is the
element id** — already stored, already stable, already re-minted on duplicate.
Jitter is generated as *points* by `roughOutlineFor`, which both the canvas and
the SVG exporter call; that shared call is the only reason two independent
renderers agree, and an e2e test asserts the exported polygon carries the exact
coordinates the canvas drew.

**1.2.0 — `frame`.** Containment is `frameId` on the child, mirroring `groupId`,
so the array stays flat and coordinates stay absolute. Membership is decided by
the element's **centre**. Frames do not nest, are never rotated (which keeps the
clip a plain rect in both renderers), and are click-through inside so contents
stay selectable.

## Two contract gaps closed

Both found by doing the work rather than by reading the docs:

1. **`SCHEMA_URL` was a hand-written literal** stamped into every saved board,
   with no test tying it to `CURRENT_SCHEMA_VERSION`. A bump that forgot it would
   have shipped files pointing at the wrong schema, permanently. Now derived, and
   the contract test asserts the named file exists.
2. **A version bump with no migration entry** is not an error, so nothing caught
   it — but it makes every previously saved board load with "no migration is
   available", which reads as data loss. Identity migrations added; the contract
   test now requires one per published version.

`docs/09-extending.md`'s worked diamond example was missing eight required steps.
Corrected, and its roughness section rewritten around the new extension point.

## Tally

278 unit/contract (was 191) and 75 e2e (was 37). Typecheck clean, `index.html`
rebuilt and committed with each change.

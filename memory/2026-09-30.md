# 2026-09-30 — Cmd-click multi-select

Branch `claude/amazing-fermi-olqccm`, on top of 122e0ed. No format change, so
no schema, CHANGELOG or version bump.

## The ask

"I am not able to select multiple objects using command key + left click.
Click selecting the next object deselects the previous one."

## Cause

`beginSelectGesture` in `src/input/controller.ts` set
`additive = event.shiftKey`. `Cmd`-click was an ordinary click, so it replaced
the selection. Nothing else in the app gave `Cmd`/`Ctrl`-click a meaning.

## What changed

- **`src/input/modifiers.ts`** (new, pure): `isAdditiveSelect(event, isMac)` is
  `shiftKey || (isMac ? metaKey : ctrlKey)`. `Ctrl` on a Mac is left out on
  purpose: it is the secondary click there (see LEARNINGS).
- **`controller.ts`**: `additive` uses it. The one flag drives both the click
  toggle and the additive marquee, so `Cmd`-drag on empty canvas also adds.
  `ControllerOptions` gained a required `isMac`. The input layer never reads
  `navigator`; `app.ts` passes `IS_MAC` from `ui/dom.ts`.
- **`keyboard.ts` `SHORTCUT_REFERENCE`**: "Shift or Cmd/Ctrl + click" → "Add to
  or remove from the selection" (it always toggled; "Add to" undersold it).

## Noticed, not changed

- On a Mac, `Ctrl`-click arrives as a primary-button `pointerdown`, which
  starts a `move` or `marquee` gesture before `contextmenu` fires. For a
  mouse, `onContextMenu` bails when a gesture is in progress, so the app's
  menu may never open on `Ctrl`-click. This is inferred from the code and
  cannot be reproduced in Linux Chromium. It needs checking on a real Mac.

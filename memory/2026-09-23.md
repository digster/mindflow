# 2026-09-23 (later) — Cmd+V pasted two copies

On `main`. One bug fix.

## The ask

> Selecting, copying and then pasting a selected object creates two copies of it.

## Cause

Two routes to `actions.paste()` for one keypress: the Cmd/Ctrl+V branch in
`input/keyboard.ts`, and the window `paste` listener in `app/app.ts`, which the
same chord triggers as its default action. The keyboard comment called them
"harmless duplicates" (and pointed at a `main.ts` that no longer exists). Both
copies land at the same +16 offset, so the second is invisible until moved.

Same root cause, second symptom: pasting a screenshot also pasted the board
clipboard, because the keydown route cannot see image data.

## Fix

`src/input/pasteGate.ts`, DOM-free, created in `app.ts` and shared by both
routes. The keydown now calls a new `onPasteShortcut` option instead of pasting.

- The native event takes the press. It is preferred because only it carries images.
- The keydown pastes on its own only if no native event arrives within 100 ms.
  This path is kept for WebKit, which fires no `paste` on a non-editable target
  unless `beforepaste` is cancelled (confirmed in WebKit's `EditorCommand.cpp`).
- A native event arriving within 1 s after the fallback has pasted is discarded.
- A second press inside the grace period supersedes the first rather than queueing.

The native listener's three `preventDefault` calls collapsed to one after the
typing-target guard.

## Tests

- e2e (`element clipboard`): one copy per Cmd+V; still pastes when native `paste`
  is swallowed (the WebKit simulation); a screenshot paste after a board copy
  inserts only the image. The first and third failed before the fix, with 3
  elements (two stacked at 116,116) and with an extra rectangle.
- 11 unit tests for the gate under fake timers, covering the arrival orders
  Playwright's Chromium cannot produce.
- 425 unit/contract and 145 e2e pass. Typecheck is clean.

## Docs

`docs/05-interactions.md` Clipboard section, `ARCHITECTURE.md` Interaction
section, `LEARNINGS.md` entry. No format change and no schema bump.

## Not done

- **A `beforepaste` listener that cancels on the board** would make WebKit fire
  native `paste` there too, bringing screenshot paste to Safari. It was not
  verifiable here: Playwright's WebKit runs key bindings with
  `allowExecutionWhenDisabled`, so it skips the menu validation that matters.
- **The native route still reads `navigator.clipboard.readText()`** instead of
  `event.clipboardData`, which it already holds without a permission prompt.

# 2026-09-23 (evening) — Recent-boards menu on the logo

On `main`. One feature, uncommitted.

## The ask

Click the logo beside the board name to reopen any recent board still stored
locally, in the spirit of the startup "Recover unsaved work?" prompt.

## What was there

`io/autosave.ts` stored ONE IndexedDB record under the key `current` and deleted
it on save, New board and Open. There was nothing to list. It also had a latent
bug: `clear()` did not cancel the 1.2 s debounce, so the write scheduled by
`load` landed after the clear. After New board or Open the next launch could
offer a blank or already-saved board as "unsaved work".

## Decisions (asked, all recommended options chosen)

1. List every recent board, not only unsaved ones. Capped at 10; saving clears
   an `unsaved` flag instead of deleting the copy.
2. Leaving a board keeps its copy. The leave prompt says so ("Leave unsaved
   changes?" / Continue) and falls back to the old "Discard" wording only when
   storage is refused or the board is empty.
3. Startup asks only about the board on screen when the last session ended, and
   only if it is unsaved. "Start blank" keeps it and does not re-prompt.

## Implementation

- `io/autosave.ts`: DB version 2 with three stores: `autosave` (contents, keyed by
  board id), `recent` (small summaries for the menu), `session` (`lastOpen`
  marker). The v1 `current` record migrates on upgrade. There is one cached
  connection plus a write queue for ordering. A snapshot of a different board
  flushes the pending one. Empty boards are deleted, not stored. Eviction prefers
  saved boards (`pickEvictions`, pure). Resolves on transaction `complete`.
- `ui/recentBoards.ts`: the popover. Rows show name, Open/Unsaved tags, count
  and relative time, plus a trash button. Arrow keys navigate and Enter presses
  whatever is focused. Unmodified keydowns stop propagating so they don't reach
  the `window` shortcuts (arrows were nudging the selection behind the menu).
- `ui/toolbar.ts`: `.mf-brand` became a button (`brandButton`) with the new
  callback `onRecentBoards`. There is also a palette command, "Recent boards…".
- `app/app.ts`: snapshots on document/load (debounced) and saved (immediate);
  `markOpen` on load; flush on `visibilitychange` hidden and on `beforeunload`.
  All `autosave.clear()` calls are gone. New `openRecentBoards`, `openRecent`,
  `loadRecent` (shared with startup) and `removeRecent`, which confirms only for
  unsaved boards and closes the popover first, since a modal and a popover
  fight over Escape. Recent boards reopen with origin `new`, never relinked to
  their file or Drive entry.
- `dialogs.ts`: `confirmDialog` gains `cancelLabel`; recovery dialog reworded.

## Tests

- 14 new e2e tests ("recent boards" block): listing and reopening, flush on
  switch, clean after save, blank never listed, removal, palette and keyboard,
  arrow-key isolation, 5 startup cases including the v1 migration, and storage
  refused (`indexedDB` getter throws).
- Updated 3 e2e tests: Discard→Continue ×2, and the reload test now polls the
  `recent` store and waits for the async recovery load.
- 12 unit tests in `test/unit/recentBoards.test.ts` (eviction, sort, time format).
- 437 unit and 159 e2e pass; typecheck clean; `index.html` rebuilt.

## Docs

`docs/06-persistence.md` (Autosave section rewritten as "Autosave and recent
boards", plus storage layout and migration), `docs/05-interactions.md` (a new
Recent boards section), README features, ARCHITECTURE (a new subsection), and
LEARNINGS (3 entries, plus a correction: Chromium DOES grant IndexedDB to
`file://`; the old entry said every browser blocks it). No format or schema
change.

## Not done / follow-ups

- The context menu has the same arrow-key nudge bug. Confirmed with a scratch
  script (y 100→102) and flagged as a separate task.
- Reopened boards are not relinked to their file handle or Drive id (deliberate:
  overwrite risk). Storing the handle and re-requesting permission is possible
  later.
- Two tabs on the same board: last writer wins. A second tab can be offered
  recovery of a board still open in the first (pre-existing behaviour).
- `.claude/launch.json` was created for the in-app preview (`npm run serve`); it
  is untracked.

# 2026-09-23 (night) — Popovers keep their keys to themselves

On `main`. One bug fix, uncommitted. This closes the follow-up flagged in the
recent-boards entry above.

## The bug

With the context menu open, ArrowDown moved the highlight *and* nudged the
selected shape 1px (y 100→102 after two presses). `installListNavigation` only
calls `preventDefault`. The window shortcut handler in `input/keyboard.ts` never
checks `defaultPrevented` and skips only typing targets, and menu buttons are
not typing targets. The same path let Backspace delete the selection, letters
switch tools and Space get swallowed by space-to-pan (so Space could not press
a menu button). The shape flyout had the same problem whenever focus was
inside it.

## Fix

- `ui/popover.ts`: the constructor adds a keydown listener on the root that
  calls `stopPropagation()` unless `metaKey || ctrlKey`, so every popover
  inherits it. This is always on, with no option: there is no popover whose
  keys should also drive the board.
- **Deliberately stricter than the old recent-boards version**, which also let
  `Alt` chords through. `keyboard.ts` ignores Alt on arrows and Delete, so
  Alt+↓ would still have nudged. `stopPropagation` does not block browser
  defaults, so letting Alt through gained nothing.
- `keyup` is not stopped, so space-to-pan can always end.
- `ui/recentBoards.ts`: removed the local listener and pointed its comment at
  `Popover`.
- The `installListNavigation` doc now says its target must be inside a Popover.

Palette and find bar: their inputs are typing targets, so the global handler
already ignored their keys. Now those keys stop at the popover root instead,
with no behaviour change. Their suites pass unchanged.

## Tests

Four new e2e tests, all confirmed failing against the pre-fix build except the
chord one, which is a guard against over-isolating:

- context menu: ArrowDown×2 + Backspace + `r` leave the sticky and the tool alone,
  while the highlight still lands on "Copy";
- context menu: Space runs the highlighted entry (Duplicate → 2 elements);
- context menu: Cmd/Ctrl+Z still reaches the app (it undoes the creation);
- shape flyout: with an option focused, `e` does not select the eraser and Space
  picks the shape.

437 unit/contract and 163 e2e pass (was 159); typecheck clean; `index.html`
rebuilt. Also checked the original repro (unfilled rectangle, right-click on
its outline) live in the browser pane.

## Docs

`docs/05-interactions.md` (a general rule under the shortcut rules, plus a
bullet in the context-menu section), `ARCHITECTURE.md` (a keyboard-routing
paragraph in Interaction), and `LEARNINGS.md` (rewrote the existing popover
entry's fix and added three details).

## Noticed, not changed

- **The command palette does not close on Cmd+K.** Its header comment says it
  "has to close itself", but nothing in `commandPalette.ts` handles Cmd+K. With
  the input focused, the keydown is a typing target, so `keyboard.ts` ignores
  it and the press does nothing. This predates this change and is unaffected
  by it.
- **Keyboard users cannot reach the shape flyout.** Opening it leaves focus on
  "More shapes", and the flyout is appended at the end of `<body>`, so Tab does
  not reach it. The new test focuses an option directly.
- **`npm run serve` overwrote the built `index.html`** with the unminified dev
  build (the in-app preview starts it). I rebuilt with `npm run build` after
  stopping it and re-ran e2e (163 pass). The artifact diff is 2 lines. Added a
  LEARNINGS entry.

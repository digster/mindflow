# 2026-09-23 (later) — Cmd+V pasted two copies

On `main`. One bug fix.

## The ask

> Selecting, copying and then pasting a selected object creates two copies of it.

## Cause

Two routes to `actions.paste()` for one keypress: the Cmd/Ctrl+V branch in
`input/keyboard.ts`, and the window `paste` listener in `app/app.ts`, which the
same chord triggers as its default action. The keyboard comment called them
"harmless duplicates" (and pointed at a `main.ts` that no longer exists). Both
copies land at the same +16 offset, so the second is invisible until moved.

Same root cause, second symptom: pasting a screenshot also pasted the board
clipboard, because the keydown route cannot see image data.

## Fix

`src/input/pasteGate.ts`, DOM-free, created in `app.ts` and shared by both
routes. The keydown now calls a new `onPasteShortcut` option instead of pasting.

- The native event takes the press. It is preferred because only it carries images.
- The keydown pastes on its own only if no native event arrives within 100 ms.
  This path is kept for WebKit, which fires no `paste` on a non-editable target
  unless `beforepaste` is cancelled (confirmed in WebKit's `EditorCommand.cpp`).
- A native event arriving within 1 s after the fallback has pasted is discarded.
- A second press inside the grace period supersedes the first rather than queueing.

The native listener's three `preventDefault` calls collapsed to one after the
typing-target guard.

## Tests

- e2e (`element clipboard`): one copy per Cmd+V; still pastes when native `paste`
  is swallowed (the WebKit simulation); a screenshot paste after a board copy
  inserts only the image. The first and third failed before the fix, with 3
  elements (two stacked at 116,116) and with an extra rectangle.
- 11 unit tests for the gate under fake timers, covering the arrival orders
  Playwright's Chromium cannot produce.
- 425 unit/contract and 145 e2e pass. Typecheck is clean.

## Docs

`docs/05-interactions.md` Clipboard section, `ARCHITECTURE.md` Interaction
section, `LEARNINGS.md` entry. No format change and no schema bump.

## Not done

- **A `beforepaste` listener that cancels on the board** would make WebKit fire
  native `paste` there too, bringing screenshot paste to Safari. It was not
  verifiable here: Playwright's WebKit runs key bindings with
  `allowExecutionWhenDisabled`, so it skips the menu validation that matters.
- **The native route still reads `navigator.clipboard.readText()`** instead of
  `event.clipboardData`, which it already holds without a permission prompt.

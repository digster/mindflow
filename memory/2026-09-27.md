# 2026-09-27 — A spinner on the Save button while a save is in flight

Branch `claude/friendly-fermi-mhzq8i`, on top of 8e7b7df. No format change, so
no schema, CHANGELOG or version bump.

## The ask

"After clicking on the save icon, let's say the board is being saved to Google
Drive, there should be some animation playing in place of the save button to
signify that the update is in process."

## What changed

- **The Save button becomes a spinner** while any save is in flight (Drive,
  local file, Save as, Drive dialog's "Save this board here"). It is Lucide's
  `loader-circle` (new manifest entry `saving`), rotating at 0.8s a turn. Label
  and title read *Saving…*, with `aria-busy="true"` and `aria-disabled="true"`.
- **150ms reveal delay**, pure CSS: both glyphs sit in the button's one grid
  cell, and `.is-busy` flips their opacity through a `0s` transition with a
  150ms delay. The unbusy rules have no transition, so the disk comes back at
  once. A save shorter than the delay changes nothing on screen.
- **Reduced motion**: the global `*` reset would spin it at 0.01ms a turn (a
  flicker). A more specific `!important` rule swaps in a 1.6s `stroke-opacity`
  pulse.
- **Saves run one at a time**: `src/app/saveQueue.ts` (new, DOM-free). While
  one runs, further requests collapse into a single follow-up (latest wins),
  and busy stays true across the handoff. The first task starts synchronously
  to keep user activation for the picker and the GIS popup. Failures propagate
  to the requester and never wedge the queue.
- **`App.requestSave`** binds each request to the board id on screen, and a
  queued follow-up is dropped if the board has changed. `save()` and the Drive
  dialog's `onSaveHere` both go through it. The old `save` body is now
  `writeBoard`.
- **Toolbar**: `buildSaveButton()` + `setSaving(busy)`. A click while busy is
  ignored (it is almost always a double click). Cmd/Ctrl+S and the palette
  still queue. `aria-disabled` rather than `disabled`, so focus survives.

## Tests

- Unit, new `test/unit/saveQueue.test.ts` (11): sync start, busy lifetime,
  idle before the awaiting caller resumes, no parallel run, collapse to latest,
  no busy blink across the handoff, own-task settlement, async and sync
  failures, follow-up still runs after a failure, superseded requests share the
  follow-up's rejection. All failed first (module missing).
- E2E, `board.spec.ts` › saving (7), with a fake `showSaveFilePicker` whose
  `close()` the test finishes by hand: spinner and labels while busy, glyph
  back and toast after; focus kept; second click ignored; two Ctrl+S mid-save
  make exactly one follow-up and the spinner never stops between; queued save
  dropped after New board; a 60ms save never shows the spinner (rAF sampling);
  reduced motion pulses. All 7 failed on the old build. A mutation check
  (guard removed) made the New-board test fail as intended.
- 539 unit (was 528). Typecheck clean. `index.html` rebuilt.
- E2E: 197 of 198. The one failure is the known `element clipboard › still
  pastes when the browser fires no native paste event` (Chromium 1194 vs 1234
  in this container). The saving and boot groups passed 30/30 with
  `--repeat-each 3`.
- Visual check at 2× in light and dark: the arc sits exactly where the disk
  was, with no shift, and turns between frames. The disk returns after the save.
  Screenshots deleted.

## Noticed, not changed

- `markSaved` after an `await` has two pre-existing races, both now easier to
  hit because the UI invites editing during a visible save. (1) Edits made
  while a save is in flight are marked clean when it lands, although the file
  does not contain them. (2) Switching boards during a save makes the *new*
  board take the old board's origin and go clean, so its next Cmd+S would
  overwrite the old board's file or Drive copy. Queued as a suggested task.
- No "Saved" confirmation on the button itself. The toast covers it.
